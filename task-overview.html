Agentic Goal Extraction & Persistence

Transforms raw manager–employee transcripts into structured goals using an AI Agent enriched with read-only DB context (via Titan/Qwen), while strictly mandating human review and an isolated CommandHandler for final database writes.

Key Architectural Separation
AI is responsible for extracting/suggesting goals, while the user and a separate backend save operation are responsible for the final database write.
AI Agent: Read-only extraction & suggestion Human in the Loop: Mandatory FE review & edits Persistence Handler: Isolated batch DB write
End-to-End Visual Execution Flow
User Input → API / Controller → CommandHandler → AI Agent (Titan / Qwen) ⇄ DB Query Tool → Structured Goals → UI Review & Edit → Save Command Handler → Database
The 4 System Building Blocks
BLOCK 01 // FRONTEND UI / UX
Text Input & Review/Edit Interface

Provides a textarea for pasting manager–employee discussions. Displays returned AI-generated goals in an editable view allowing fine-tuning prior to saving.

"User enters the summary/transcript... Based on the summary/transcript, an AI agent will extract the goals and display them to the user. User is able to edit the goal list and then proceed to saving it."
BLOCK 02 // COORDINATION CQRS
CommandHandler & CQRS Separation

The API/Controller delegates orchestration to a dedicated CommandHandler. It decouples the web layer from agent coordination without polluting handlers with direct LLM calls.

"The API/controller passes the request to a CommandHandler. The CommandHandler coordinates the AI-related operation rather than directly handling the LLM interaction itself."
BLOCK 03 // INTELLIGENCE AI AGENT
AI Agent + Read-Only DB Tool

Agent uses an OpenAI-compliant Qwen endpoint (via Titan URL) paired with a database query tool to inspect relevant context before returning schema-validated structured goals.

"A tool which can query the database is needed to check for our relevant data... You can use Titan url and Qwen model with your API key (it's OpenAI compliant)... LLM returns a structured output."
BLOCK 04 // PERSISTENCE TRANSACTION
Save Command Handler & Database Write

The write boundary is strictly isolated. Only after the user confirms and triggers the save action does the backend execute an atomic write to store multiple goals.

"On FE the user can still edit the goals (AI won't have the capability to write to the database). When everything is filled in properly, the user saves the goal to the database (an additional command handler which saves multiple goals may be needed)."
